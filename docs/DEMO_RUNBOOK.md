# 研修担当R1 デモ運用手順書

これは2026-11-14時点の旧手順で、Strata・8765・クリック式移動を前提とする。現在の8770パネル、GPT API、押下中の歩行、起動・終了は [ナレッジ集](KNOWLEDGE_BASE.md) と [即興デモの運用手順](LIVE_DEMO.md) を使う。以下の数値やコマンドを現行設定として使わない。

PCマイク → faster-whisper → Z840 Strata → Ichiro日本語音声 → R1スピーカーで会話する。
パネルは研修担当R1に固定、自動身ぶりオンが既定。R1のOnboard PCにはログインしない。
今回追加した自動通話・帽子の動作は実マイクと実機での検証が残っているため、以下を段階的に確認する。

## 1. 担当と事前準備

実機の動作時は、PC担当とE-Stopを持つオペレーターを分ける。初めて動かすコードは吊って確認し、床では周囲2m以上を空ける。
起動・起立・停止の操作は使用実機とスタッフの運用手順を優先する。Locked Standにはバランス制御がない。

- `pixi install` と `pixi run verify-sdk` を完了する。
- Z840のSSH接続情報を [README](../README.md) の環境変数に設定する。StrataにはOpenAI APIキー不要。
- 音声認識モデルの初回ダウンロードをネットのある場所で済ませ、PCマイクとIchiroの音声を確認する。
- 実際の台本・作業指示書を受け取る。まだ未提供なら、業務の手順・指定値を作らず、人格と会話操作だけを確認する。
- 新しい台本の確認手順は [新人研修デモの組み立て方](TRAINING_DEMO.md) を使う。

## 2. R1なしでパネルを確認する

```powershell
pixi run ui --local
```

[パネル](http://localhost:8765) を開き、表示が「研修担当R1（Strata）」であることとStrataの接続表示を確認する。
人格は既定で固定される。教材や会話をリセットしても人格は変わらない。
文字だけを先に試すときは `--no-stt` を付ける。その場合、通話ボタンは利用できない。

1. 文字で「どんな研修を手伝ってくれる？」と送り、返事がPCから聞こえることを確認する。
2. 「通話を開始」を押し、マイクに向かって1文話す。
3. 話し終わって約0.8秒の無音で自動送信され、認識結果と返事が出ることを確認する。
4. 返事が終わると「聞いています」に戻ること、返事中の音を次の発言として取り込まないことを確認する。
5. 次の質問を話す。毎回ボタンを押す必要はない。返事への割り込みはできない。
6. 「通話を終了」を押す。処理中の返事が後から再生されないことを確認する。

このモードではR1に動作を送らず、選ばれた身ぶりを画面・ログで確認する。
ノイズで勝手に送信する場合は `--call-threshold` を上げ、文の途中で切れる場合は `--call-silence` を長くして起動し直す。
実際の会場で適切な値を測って調整する。

## 3. 教材を読み込む

通話を終了し、返事や録音が終わってから操作する。

1. 「新人研修の台本・作業指示書」→「資料を読み込む」を開く。
2. UTF-8の `.txt` / `.md` を選ぶか、本文を貼り付ける。PDF・Wordは本文をテキストにして貼り付ける。
3. 資料名を付けて「研修資料として読み込む」を押し、一覧に名前が出ることを確認する。
4. 教材に書かれた内容と、書かれていない内容を質問し、根拠のある返事と確認の必要な点を区別できるか確認する。

上限は1件8,000文字、合計12,000文字、8件。保存先はGit対象外の `logs/training/materials.json`。
読み込んだ本文は各返事の依頼に含め、SSH経由でZ840のStrataに渡す。利用してよい資料だけを読み込む。
追加・削除すると会話履歴をリセットする。単に「会話をリセット」を押した場合は教材と人格が残る。
この処理は教材の参照で、LoRAの追加学習やStrataのモデル変更ではない。

## 4. 実機の音声を確認する

1. オペレーターがR1を起動し、起動完了と使用モードを確認する。
2. R1の指定LANポートとPCをつなぐ。使用する有線アダプタと参加環境のIP指定を確認する。
3. LAN設定スクリプトを使う場合、まず `-DryRun` で対象を確認する。

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\setup_lan.ps1 -DryRun
   powershell -ExecutionPolicy Bypass -File scripts\setup_lan.ps1
   ```

   実行時はアダプタ名・固定IP・ネットワーク種別を変更し、pingと日本語発話を試す。元の設定は `.lan_backup.json` に保存する。
4. LLM不要の一言で音を確認する。

   日本語はPCのIchiroで合成し、`PlayStream` でR1へ送る。中国語・英語用の標準 `TtsMaker` に日本語を渡す構成ではない。

   ```powershell
   pixi run chat -i Ethernet --say "音声の接続テストです"
   ```

5. パネルを音声のみで起動する。

   ```powershell
   pixi run ui -i Ethernet --volume 100 --gain 9 --no-motion
   ```

6. 文字入力で会話し、次に通話ボタンで会話する。PCでの成功とR1で実際に聞こえることを分けて確認する。
7. 通話終了後に遅れて発話しないことと、スピーカー音を次の発言として認識しないことを確認する。

## 5. 身ぶりを加える

使用実機のモード・利用可能な腕動作と周囲をオペレーターが確認する。パネルの送信はRunning状態でだけ行う。
自動身ぶりのスイッチをオンにするか、`--no-motion`を外して起動する。

```powershell
pixi run ui -i Ethernet --volume 100 --gain 9
```

Strataは発話ごとに身ぶりを選ぶ。必要がなければ `none` を選べる。「手を振って」「拍手で応援して」などで順に確認する。
歩行は次の指定で有効にし、Running状態と現場の準備を確認した場合に、明示的な移動依頼に限って短時間実行する。説明やあいさつだけでは歩かない。

```powershell
pixi run ui -i Ethernet --body-control --velocity-127-compatible --forward-speed 0.3 --forward-duration 2 --volume 100 --gain 9
```

上のコマンドでは、実機で目視確認した前進だけを0.3m/s・2秒に設定する。会話とボタンで同じ条件を使う。後退・左右横移動は0.1m/s・1秒、左右旋回は0.2rad/s・1秒の指令で、これらの実移動はまだ確認できていない。
前進の指定を省略した場合も0.1m/s・1秒になる。提示されたG1用 `sample-walk` をそのままR1で実行しない。
この実機の応答127は、速度指令7105に限り明示的な互換設定で扱う。127だけで動作・停止の成功と判断しない。
歩行中は最新の脚の状態を10Hzでポーリングし、CRC・0.5秒未満の鮮度・機体情報・モーター異常を確認する。状態不正時はゼロ速度を送り、停止直後に新しい観測で0.5秒以上の脚の静止を最長2秒間確認する。

1. パネルでRunning状態と歩行ボタンが有効であることを確認し、短い移動を1回だけ指示する。状態監視が不正ならプログラムが移動を見送る。
2. ゼロ速度の送信と脚の静止の表示を確認し、オペレーターが実際の移動・停止を目視で確認する。
3. 停止未確認や状態異常があれば次の動作に進まない。脚の変化だけでは移動方向や距離・角度を確認したことにはならない。

新しい関節動作は現在保留中。歩行停止ボタンはゼロ速度の指令であり、コントローラーの緊急停止の代わりではない。
LLMの形式エラー時は1回だけ文章で取り直し、その回の身ぶりを付けない。JSONをそのまま読み上げることはしない。

帽子の演出 `hat_tip` は、実機に登録された専用教示動作 `hiyari_hat_v1` が一覧で見つかったときだけ使う。
[hat_gesture.json](../r1_motion/hat_gesture.json) は未検証の演出案で、関節軌道でもアップロード可能な動作データでもない。
専用動作の教示・登録・実機検証はまだ行っていない。未登録なら既定では動作を見送る。

危険を解消した後の模擬研修で「いまの、何かわかるか？ ヒヤリハットだ。」といった振り返りに使う。
現に危険が続いているときは冗談や帽子の身ぶりを使わず、作業を止めて担当者に確認する。
`--hat-fallback`を明示するとプリセット26の頭上の手振りで代用できるが、専用の帽子動作とは異なる。

## 6. トラブル対応

| 症状 | 確認すること |
|---|---|
| R1の様子がおかしい・転びそう | オペレーターがコントローラーで緊急停止。パネルの通話終了をロボット停止の代わりに使わない |
| Strataに接続できない | Z840の到達性、SSH環境変数、鍵とknown_hostsの設定、既存Strataの状態 |
| 研修担当R1なのにOpenAIキーが必要と言われる | `pixi run ui` を使用しているか、人格が `mentor` か。従来の `pixi run chat` はOpenAI用 |
| 通話ボタンが押せない | STT準備完了、`--no-stt`の有無、ほかの処理・一回録音の終了 |
| 騒音を発言として拾う | マイク位置、会場の音、`--call-threshold`を調整 |
| 文の途中で送信する | `--call-silence`を長くし、一人ずつ話す |
| 返事が遅い | Z840の同時利用、SSH・回線、STTがCPUへ切り替わっていないか。モデルを勝手に入れ替えない |
| R1から音が出ない | LANアダプタ、ネットワーク種別、起動完了、音量。一言の発話テストを再確認 |
| 帽子の身ぶりが見送られる | `hiyari_hat_v1`の実機登録・一覧・使用モード。未登録なら想定どおり |
| 教材が読み込めない | UTF-8の.txt/.mdか、文字数・件数、空の本文やPDF/Wordを送っていないか |

`logs/` の最新のUIログとturns.jsonlを確認する。会話と教材の内容を含む可能性があるため、共有前に内容を確認する。

## 7. 終了

1. 「通話を終了」を押し、録音と返事が終了したことを確認する。
2. 必要なログを保存し、PC側のターミナルでCtrl+Cを押してパネルを終了する。
3. オペレーターが実機の正規手順で停止する。立ったまま電源を切らない。
4. LANの復元が必要なら `powershell -ExecutionPolicy Bypass -File scripts\setup_lan.ps1 -Restore`。
5. 教材を消す場合はパネルで削除する。会話リセットでは教材ファイルを消さない。

標準R1と比較する必要がある場合だけ `--allow-persona-switch` を付ける。標準R1を選ぶとOpenAIキーとAPI利用が必要。
