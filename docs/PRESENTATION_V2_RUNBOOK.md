# 発表シナリオver2の進め方

**位置づけの変更**: 本番の返答はLLMがその場で生成する。以下の31段の固定再生と以前作成したWord版は、発話・動作の回帰試験用として扱う。発表の役割と場面の目的だけを即興対話へ引き継ぐ。現在の運用方針は [即興デモ](LIVE_DEMO.md) を参照。

原案のシーン0〜5に台詞・身ぶり・歩行を対応付けた過去の回帰試験用資料。現在、仮想R1は凍結しており、下記の接続手順は再開指示まで実行しない。
元のWord文書は変更せず、`scenarios/presentation_v2.json` を再生用の台本とする。本編24段、時間に余裕がある場合の補足7段の計31段。

## 場面と動作

| 場面 | 台詞と動作 | 進行の合図 |
|---|---|---|
| 0 登場と挨拶 | 前進と登場の台詞、ゼロ速度、固定の自己紹介と手振り25、短い挨拶と胸に手33 | 背景を投影し、新人役が挨拶 |
| 1 手順説明 | 椅子の説明位置へ前進、ゼロ速度、AとBの説明で前方へ腕を伸ばす31 | 新人役もボタン表示の位置を示す |
| 2 押し間違い | 落ち着いた声かけ、強調35、正しいAの方向へ腕を伸ばす31 | 人がCを押した事象を確認してEnter |
| 3 振り返り | 危険解消済みの模擬設定でヒヤリハットの台詞、親しみやすい冗談と胸に手33 | 新人役の気付きの発言 |
| 4 まとめ | R1は待機し、プレゼンターが説明 | 本編終了 |
| 5 任意の補足 | 仕組みの説明を3段に分け、胸に手33、前方を示す31、強調35。手振り25で開発者へ引き継ぐ | 残り約2分を人が確認した場合だけ開始 |

前進は各0.3m/s・2秒の指令。毎回ゼロ速度を送り、終了を待つ。移動距離を保証する指令ではない。
初期位置P0、挨拶位置P1、椅子の前P2は、同じ向きの前進だけで移れる配置を想定する。後退・旋回・新しい関節軌道を追加していない。
発話とその場面の動作は重ねるが、歩行と腕の動作は順に実行する。保持型の腕動作は99で解除し、次の段へ進む。

31は前方へ腕を伸ばすプリセットであり、特定のボタンへ指先を自動で合わせる機能ではない。椅子・ボタン表示・向きは人が事前に決める。
帽子の専用動作 `hat_tip` は未実装の演出予約として表示し、送信しない。実装済みの姿勢は33を使う。
A/B/Cは模擬ボタンであり、実際の設備を操作しない。押し間違いの事象も人の合図で渡し、映像認識したとは説明しない。

## 仮想リハーサル

仮想リハーサル再開時は仮想器を1台だけ使い、追加起動しない。シナリオと依存コードはこの版に含まれ、別PCではGitに含めない録画フォルダとPC固有設定も必要になる。

```powershell
# 仮想器が起動していない場合だけ、別ターミナルで起動
pixi run python local_tools/virtual_r1.py --fsm 811 --mute --snapshot logs/r1_snapshot_20261114_172704

# 通信しないプレビュー
pixi run python scripts/virtual_scenario.py scenarios/presentation_v2.json

# 本編だけ。各段の前にEnterを押して進める
pixi run python scripts/virtual_scenario.py scenarios/presentation_v2.json --end-step s4_presenter --run-virtual --pc-audio --interactive

# 残り時間に余裕がある場合の補足
pixi run python scripts/virtual_scenario.py scenarios/presentation_v2.json --start-step s5_time_cue --run-virtual --pc-audio --interactive
```

新人役とプレゼンター・ナレーションの文章は表示だけで、R1の声では読まない。本人が話し終えてから、進行役がEnterで次の段へ進める。Ctrl+Cで終了する。
ランナーの実行先はループバック固定で、実機のEthernetへ変更する引数はない。

## 所要時間

以下は旧音声実装での計測記録であり、本番の即興対話や、男性音声を正しく選択するよう修正した後の所要時間には使わない。旧実装では指定した声を選べなくても既定音声へ切り替わっていた。現在は実際の声名を確認する方式へ修正している。

Microsoft Ichiro、rate0でR1の台詞を合成した長さは合計173.13秒。新人役・プレゼンター・ナレーション、Enter待ち、動作待ちの延長は含まない。
補足説明の3段は19.680秒、19.175秒、18.425秒。合計57.28秒、間の0.5秒を2回含めて58.28秒となる。
本番の全体時間は、人の台詞と間を含めたリハーサルで決める。

## StrataからGPT APIへ切り替える

固定台本の再生はLLMを呼ばず、返答待ちを挟まない。応答先の切替は、自由な質問への受け答えに適用する。
研修担当R1の人格、教材、直近の会話、動作制約は共通で、パネルの「研修担当R1の応答先」から選ぶ。
通話・録音・処理を終えてから切り替え、接続表示を確認する。処理中の自動切替や並列実行は行わない。

```powershell
# GPT APIで会話のローカル確認を始める。既存のAPIキー保存先を利用
pixi run ui --local --mentor-backend openai
# Strata側の通信1回の待ち時間を指定する例
pixi run ui --local --mentor-backend strata --strata-timeout 10
```

GPTの既定モデルは既存設定の `gpt-5-mini`。APIは従量課金で、鍵を台本やリポジトリへ書かない。
Strataの待ち時間は通信1回の制限であり、形式再試行や初回モデル取得を含む全体時間の保証ではない。
発表教材は `scenarios/presentation_v2_context.txt` からローカルの教材保存先へ読み込み済みで、応答先を変えても引き継ぐ。

ローカル確認では、同じ模擬ボタンA/Bの質問がStrataで10.01秒のタイムアウトとなった後、GPT APIへ手動切替し、教材に沿う回答と強調の身ぶりを3.23秒で得た。これは1回の確認で、平均応答時間や本番の保証ではない。記録は `logs/presentation_gpt_fallback_check_20261114.json`。
