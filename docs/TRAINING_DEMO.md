# 新人研修デモの組み立て方

研修担当R1の人格は固定指示で毎回維持する。教材を参照して受け答えする仕組みで、LoRAの追加学習は実施していない。
実際の台本・作業指示書はまだ未提供のため、ここには製造工程や指定値を作って載せない。

## 現在の作業：仮想リハーサル

実機の試験時間を終え、発話と動作の組み合わせはClaude作成の仮想R1で組む。
`scenarios/training_rehearsal.json` に、自己紹介・指示書への導入・前進と停止・模擬ミスへの声かけ・危険解消後の振り返りを置いた。
帽子は未実装の演出予約。具体的な機械の操作手順は含めない。

```powershell
pixi run python scripts/virtual_scenario.py scenarios/training_rehearsal.json
```

既定は通信なしのプレビュー。[仮台本の使い方](VIRTUAL_SCENARIOS.md) に、ループバック上の仮想R1への実行とPC音声の選択を記載している。

## 自己紹介の軸

`r1_chat/identity.py` に、教材や会話履歴とは独立した自己像を置く。

- 目的は、工場で新人に機械の操作方法を教えること。
- 仕組みは、PCで聞き取り、Strataが説明と動作候補を選び、プログラムが音声・指令へ変換し、実行条件を確認してR1へ送ること。
- 育てる理由は、新人の操作ミスによる事故を防ぎ、安全に作業できるようにすること。

チャットで直接自己紹介を頼んだときと、パネルのあいさつボタンは、次の同じ固定文を使う。

> 俺は、工場で新人に機械の操作を教えるR1だ。操作ミスによる事故を防ぐために、君と手順と理由を確かめる。AIが説明と身ぶりを選び、プログラムが形にし、安全のための確認処理が実行条件を確かめるんだ。分からないことは何度でも聞いてくれ。

「AIは何をするか決める。プログラムはどう実現するか決める。安全機構は実行してよいか決める。」を設計思想とし、状態監視とログで支える。
現在の確認処理は動作一覧・機体の状態・動作の重複などを確認する。人や障害物、工場設備の危険をすべて検知したり、機械を直接操作したりする仕組みではない。
事故防止という教育目的と、安全の保証・実作業の実施許可を区別して説明する。

## 台本を受け取った後に決めること

1. 研修の対象、学習者、実演する範囲を確認する。
2. 台本と作業指示書から、教える順序・確認質問・見せる身ぶりを対応付ける。
3. 仕様値、工具、合否基準、危険箇所など、資料にない条件を担当者に確認する。
4. 架空の指示書を使う場合は模擬研修と明示し、実作業の承認資料には使わない。
5. UTF-8の.txt/.mdまたは貼り付け文章としてパネルに読み込む。1件8,000文字、合計12,000文字、8件まで。

## 最初の会話確認

`pixi run ui --local`で起動し、読み込んだ資料について説明・確認問題・聞き直しを試す。
資料にない指定値を質問し、推測で数値を作らず確認を求めることも確認する。
「会話をリセット」後も人格と教材が残ること、教材の追加・削除後は古い会話の前提が消えることを確認する。
教材本文はPC内に保存され、各返事の依頼とともにSSH経由でZ840へ渡る。

## ユーモアと身ぶり

失敗を隠さず相談できる、気さくな熟練工という話し方を使う。学習者を見下したり、間違いを笑ったりしない。
危険が続いている場面では冗談と動作を控え、停止と担当者への確認を優先する。

帽子の演出は、危険を解消した後の模擬研修でヒヤリハットを振り返る場面に使う。
例：「いまの、何かわかるか？ ヒヤリハットだ。」

`r1_motion/hat_gesture.json`は演出用の絵コンテ。実機の関節値や制御軌道は入っておらず、登録も未実施。
新しい関節動作の作成・実機送信は現在保留中なので、帽子の専用動作を新たに教示・実行する段階には進めない。
再開後は実機に合わせて教示・確認し、専用名`hiyari_hat_v1`で登録された動作が見つかった場合だけ実行する。
未登録なら動かさない。頭上の手振り26による代用は`--hat-fallback`を明示した場合だけで、専用動作の完成とは扱わない。

## 移動を使う演出と、現在の関節動作の保留

歩行を含む全身駆動と関節制御は開発上許可されている。現在は新しい関節動作を保留し、既存の腕プリセットと短時間の歩行・旋回を確認する。
実機の歩行をパネルから使う場合は `--body-control` を付け、Running（811）と周囲の空間を確認する。`--local` では送信しないプレビューとなる。

```powershell
pixi run ui --local
pixi run ui -i Ethernet --body-control --velocity-127-compatible --forward-speed 0.3 --forward-duration 2 --volume 100 --gain 9
```

通常の設定は並進0.1m/s・旋回0.2rad/s、各1秒。上の実機用設定は前進だけを0.3m/s・2秒に変え、終了時に速度ゼロを送る。現在は仮想器での構成を優先し、このコマンドで実機試験を再開しない。
会話では利用者からの明示的な移動依頼に対応する候補だけを実行する。説明中にAIが移動を選んだだけでは送信しない。
起立やモード変更は自動化しない。速度と時間の指令から正確な距離・角度や到達を約束しない。
実機では小さな指令では移動を確認できず、0.3m/s・2秒で前進・停止を目視確認した。最低速度や正確な距離を特定したわけではない。仮想器での合成動作を実機の合格と扱わない。

`r1_motion/joint_control.py` は関節軌道のオフライン検査・100Hzプレビューだけを行い、実機には送らない。
再開後に使うための確認済みプロファイルには、機体ID・関節名とindex・角度限界・最大速度・出典・ファームウェアを明示する。
CRC検証済み状態の記録、測定時刻、現在角との連続性も照合する。実機の関節値や可動限界を架空の教材から作らない。
出力の`executable: false`は、実機実行用データではないことを表す。

## デモ前の合格確認

- 台本の要点を短く説明し、質問に資料を根拠として答える。
- 不明な指定値や実作業の安全性を、推測で断定しない。
- 通話開始後、話し終わりで自動送信し、返事中の音を取り込まない。
- 通話終了後に、処理中だった返事を新たに再生しない。
- 身ぶりは実機の確認済みモードでだけ行い、専用の帽子動作が未登録なら見送る。
- 自己紹介で目的・仕組み・育てる理由を説明し、会話リセットや教材によって自己像が変わらない。
- 歩行は有効化・明示的な依頼・Running状態を確認し、短時間で止まる。新しい関節動作は送らない。

実マイク、自動通話、R1スピーカーの連続会話と帽子の実機動作は検証が残っている。
PCのローカル確認を終えてから、[デモ運用手順書](DEMO_RUNBOOK.md)に従って実機の音声、最後に身ぶりを確認する。
