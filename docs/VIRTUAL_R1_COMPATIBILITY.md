# 仮想R1との接続・台本構成メモ

2026年11月14日時点の `local_tools/virtual_r1.py` のコード確認に基づく過去の検討記録。現在、仮想R1は凍結しており、以下の起動手順は再開指示まで実行しない。実機と明示的なローカル試験の運用は [即興デモ](LIVE_DEMO.md) を参照。

仮想R1は、実機録画を再生するDDS・RPCエミュレーターである。物理演算、3D表示、床面上の位置・向きの計算は行わない。台本の順序、発話、動作要求、待ち合わせを確かめる用途に使い、実機の歩行・衝突回避・停止性能の証明にはしない。

| 項目 | 現在の動作 |
|---|---|
| 接続 | 既定は `Loopback Pseudo-Interface 1`、DDS domain 0。同じインターフェースにLowStateの発信者が見えると起動を拒否する |
| サービス | `sport`、`arm`、`voice`、`motion_switcher`、`robot_state`。既存パネルやデモの呼び出しを受ける |
| 状態 | 保存済みのLowState、IMUなどを繰り返し配信。FSMと腕の保持状態を模擬する |
| 歩行 | 速度要求に応じて股・膝の角度を合成する。仮想の移動距離や旋回角は計算しない |
| 発話 | PlayStreamの音声をPCで再生。`--mute` は無音だが、音声の長さに応じて待つ |

## 別PCへ引き継ぐもの

仮想器本体 `local_tools/virtual_r1.py` と、読み取り専用の `r1_snapshot.py`・`r1_types.py` はコミット `42a1d77` に含まれる。ファイルの場所は変えていない。
録画データはGitに含まれないため、`logs/r1_snapshot_20261114_172704/` を丸ごと同じ相対位置へコピーする。起動時に `rpc.json`、`discovery.json`、`types.pkl`、`raw/` の録画を使う。

```powershell
pixi run python local_tools/virtual_r1.py --fsm 811 --mute --snapshot logs/r1_snapshot_20261114_172704
```

仮台本・シナリオランナー・歩行や通話のコードもこの版に含まれる。別PCでは、Gitに含めない録画データとPC固有設定を別途用意する。

## 現在のEngineへ接続する際の差分

**18:18の更新で、周回ごとにtickを先へずらし、CRCを再計算する処理が実装された。** 約15秒の録画を繰り返したとき、元のtickへの巻き戻りを `MotorFeedbackMonitor` が拒否する問題への修正である。コード上の変更は確認済みだが、Engineが2周目以降も正常な観測として受け入れる実行確認はまだ行っていない。Engineの10Hz監視は、CRC、tickの進行、0.5秒未満の鮮度、機体情報、モーター異常を確認する。録画の `mode_machine=1`、`mode_pr=0` は現設定と一致するが、コード修正だけでこれらの条件を満たしたとは扱わない。

`--speed 4` で4倍速になるのは腕・起立・保持時間で、歩行のduration、音声、録画の再生時間は変わらない。発話と動作の実時間の重なりを確認するときは、この違いを区別する。`voice_stop` は待機中の音声を消すが、再生中のチャンクを中断しない。

実機より条件が緩い箇所もある。速度指令は811だけでなく816でも受理し、任意のFSMへの変更も受理する。任意名の教示動作は待つだけで成功を返す。合成した脚の揺れや成功応答を、実機の動作成立や帽子動作の登録・再生確認に読み替えない。

## 実機結果との区別

当日の実機では小さい速度・短時間の指令だけでは前進を確認できず、**0.3m/s・2秒の前進と、その後の停止をユーザーが目視確認した**。これは今回の運用上の確認であり、メーカー指定の最低速度でも、距離・停止性能の保証でもない。仮想R1内の合成歩行の閾値も、実機仕様を表す値ではない。

台本構成のプレビューはDDSを初期化せず、通信を伴う試行はループバックに限定する。仮想R1自身は `-i` の変更を禁止していないため、実行側でも接続先を制限する。実機とのサービス重複を避け、仮想試行からEthernetや新しい低レベル関節指令へ切り替えない。
